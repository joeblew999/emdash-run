# ADR-0007 — Rework onto emdash@1.1.0 using `.src/` and official templates

## Status

Accepted. Supersedes [0006](0006-templates-src-clone-and-run.md). Revises
[0002](0002-cad-schema-as-seed.md) and [0005](0005-emdash-local-cli-task.md).

## Context

`emdash-run` was pinned to `emdash@0.1.0`. EmDash has since released `emdash@1.1.0`
(and requires pnpm 11.9.0 / node ≥ 22.16). The old harness depended on emdash's
*internal* code in ways that no longer make sense:

- it ran the monorepo's integration-test fixture (`demos/cloudflare`) as the live site;
- it pinned `@cloudflare/kumo` by rewriting symlinks, because the fixture's monorepo
  workspace pinned a version the admin UI could not use;
- it symlinked five extra first-party plugins into the fixture's `node_modules`
  because the fixture did not declare them;
- it copied config over a read-only monorepo clone;
- it read the CAD seed through the monorepo's built CLI (`packages/core/dist/...`)
  against a local `data.db`.

None of that is needed once the site is a real, published-package-consuming site.
`emdash@1.1.0` also changes two things that matter:

1. **Plugin discovery moved from the Marketplace to a registry.** The `marketplace`
   integration option is now **deprecated** and only keeps *legacy* plugins
   updatable. New discovery/install uses `registry` (`https://registry.emdashcms.com`
   by default when a sandbox runner is configured).
2. **The best-practice host is an official template.** EmDash ships
   `emdash-cms/templates` (auto-synced from the monorepo), each template in a Node.js
   and a `-cloudflare` variant, consuming the published `emdash` npm package.

## Decision

Adopt the `.src/` + official-template model (the direction that was merely
*proposed* in ADR-0006), and drop the monorepo-internals coupling.

### Layout (all gitignored)

| Path | What | How it is produced |
|------|------|--------------------|
| `.src/templates/` | clone of `emdash-cms/templates` | `mise run src:clone:templates` |
| `.src/site/` | **the host site**, a copy of the chosen template | `mise run site:sync` (`rm` + `cp -R`) |

The host template is **`starter-cloudflare`**. `blank` was retired upstream
(emdash-cms/templates #55); `starter-cloudflare` is the closest live equivalent —
unopinionated base plus the Cloudflare/D1/R2 stack this repo needs.

### What the site consumes

`.src/site` depends **only on published npm packages** (`emdash`, `@emdash-cms/cloudflare`,
`@astrojs/cloudflare`). It does **not** reference the monorepo workspace. This is what
removes the kumo pin and the plugin symlink hacks.

`config:apply` writes three things into `.src/site`:

- `astro.config.mjs` ← `config/site.astro.config.mjs`
- `wrangler.jsonc`   ← `config/site.wrangler.jsonc`
- `seed/seed.json`   ← generated by `scripts/merge-seed.mjs`

### Seed

EmDash applies the seed automatically on the first request when the database is empty,
using the `emdash.seed` path from the site `package.json`. There is no separate seed
command for D1 (ADR-0002's CLI seed flow is gone). `scripts/merge-seed.mjs` merges the
template's demo seed with the CAD collections from `config/cad.seed.json`, so the
template's pages render *and* the CAD collections exist.

### Plugins

- in-process `plugins:` — `@emdash-cms/plugin-forms`, and `@plat-trunk/emdash-plugin`
  (the latter is `format: "standard"`: a descriptor with an `entrypoint` module that
  default-exports `{ hooks }`. A bare `definePlugin({...})` result is rejected in
  `plugins: []` — it has no entrypoint to bundle.)
- sandboxed `sandboxed:` + `sandboxRunner: sandbox()` — `@emdash-cms/plugin-webhook-notifier`

`@emdash-cms/plugin-audit-log`, `-color`, `-embeds` and `-ai-moderation` are dropped:
they existed only to exercise the plugin system, and `ai-moderation` additionally needs
a Workers AI binding. They are one line each to re-add.

### No monorepo clone

The legacy Marketplace is deprecated in 1.1.0 (discovery moved to the registry), and
it is **not** part of this harness at all: no emdash monorepo clone, no `:8787`
worker, no `marketplace:*` tasks. Plugin work uses `plugins: []` / `sandboxed: []`
with the site's own `emdash` CLI; discovery uses the hosted registry.

> **Update (2026-10-05).** The clone is available again **on demand** via
> `mise run src:clone:emdash` — shallow, tag-pinned, ~100 MB, *not* installed. It is for
> reading EmDash's own source (its `dist` types are not always enough) and for running
> the local registry aggregator (`apps/aggregator`). It remains off the default path.

## Consequences

- Default setup no longer clones or builds the emdash monorepo → much faster, no kumo
  pin, no plugin symlink hacks.
- The site is a real EmDash site, so the harness exercises the same path users take
  (and the same path the not-yet-done Cloudflare deploy will take).
- `mise run server:reset` must wipe the D1/miniflare state (`.wrangler/state`), not
  `data.db`.
- The CAD seed is now merged rather than applied verbatim; reference ids in
  `config/cad.seed.json` still use the exported `$ref:<ulid>` form and are validated
  during dogfooding.
- No emdash monorepo clone and no local marketplace worker: the whole flow needs only
  `.src/templates` + `.src/site` and the site's own `emdash` CLI.
