## Signing in — what was found, and what is kept

Every way is kept, on purpose, to be tried (the owner, 2026-10-07). Security of these test sites is
a later job, by the owner's decision: nothing is switched off or guarded while exploring.

| way | task | found by running it |
|---|---|---|
| a machine, no browser | `signin:token` | EmDash accepts an API token before any other sign-in, under Cloudflare Access too. The task writes an administrator and the token's hash into the site's database (D1 with wrangler; a Node site's SQLite file with Node). Works on this machine's built site and, with `-- --live`, on a deployed one |
| people, by Cloudflare Access | `signin:access` | needs a Cloudflare token with Access edit rights (the owner's is in fnox); wrangler's own login gets 403. A service token gets a machine *through* Access and is not a user: it still needs the API token above |
| a machine, through EmDash's pages | `signin:passkey` | Playwright and a simulated passkey complete the real wizard and CLI login. Needed only to test those pages |
| a person, a signed-in window | `signin:open` | Playwright; uses the saved token (and Access pass), else the saved passkey |
| a login provider (GitHub…) | none — site config | the button shows in the setup wizard on a built site; a real sign-in needs an OAuth app |

`emdash whoami` behind Access: EmDash's does not send the Access pass. Two fixes are both in —
A: `signin:token -- --live` also writes EmDash's own sign-in store; B: the `emdash` task answers
`whoami` when the token is only in the environment (CI). C (use `schema list`) and D (report it
upstream) remain.

What this machine saves is under `~/.config/emdash-run/`, named by site — a deployed site by its
address, a local one by its folder as well as its port — and a token is named after the machine
that made it, so many sites and many machines do not collide.

  allows task-scoped fnox secrets", mise 2026.10.4). **Run 2026-10-08, and decided: not in
  `tasks.toml`.** mise refuses it for exactly the tasks a project gets from here:
  - **Run** (mise 2026.10.4, fnox 1.39.0, `experimental = true`, `[secrets.fnox]`; a throwaway
    branch with three probe tasks, included by git as every project includes these):
    a task of the project's own with `secrets = [...]` → gets the value; a task in an included
    **local** file → gets it; a task from the **git include** → "comes from a remote source … and
    cannot list secrets"; the same for `{{ secrets.X }}` in its env.
  - **What does work for a git-included task:** the grant on the command line —
    `mise run --secrets CLOUDFLARE_API_TOKEN,CLOUDFLARE_ACCOUNT_ID signin:access`. Seen with a
    probe task, not yet with `signin:access` itself (it reads the environment first, so it should).
  - **Kept:** `admin/access.mjs` reads the environment, then `fnox get`. It works on any mise,
    needs no experimental setting, and on Windows and CI mise would call the fnox CLI anyway.
  - Also a reason not to: `secrets` on a task makes mise older than 2026.10.4 reject the file —
    every developer on an older mise would lose every task.
  - If mise later lets a project say "this include may list secrets", look again.
