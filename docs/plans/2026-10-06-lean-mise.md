# 2026-10-06 — A lean mise: flows a dev remembers, logic that is DRY and tested

**Status:** active — **1 of 6 done**

`mise.toml` is how a developer works on EmDash here — dev, content, plugins, ops. It should be a
short list of **flows**: one command per job, each doing everything that job needs. It grew into
the opposite: 2582 lines, 130 tasks, 633 lines of comments, most of it a task per CLI subcommand
and the story of every bug.

## Measured on 2026-10-06, before any of this

| | |
|---|---|
| lines in `mise.toml` | 2582 — 633 of them comments |
| tasks | 130 — 115 visible, 15 hidden helpers |
| tasks that only relay one CLI command | 35 |
| tasks that only alias another task | 14 |
| top-level flows a dev actually types | 9 |
| helper code repeated across bodies | the exit-code wrapper ×3, the dev-database lookup ×4, the `--url` handling ×4 |

**Does it work?** Ran every task that is safe to run unattended: 33 tasks, 31 exited 0. The two
that did not: `plugin:search` (the default environment pointed it at a local registry nothing
runs), and `emdash:doctor` exited 0 while reading the **wrong database** and reporting "no users".
Never run by this audit, so unknown: `registry:*` (8) and `plugins-site:*` (3), which need the
EmDash monorepo built; `site:check` and `site:deploy-dry`; `deploy` itself; the interactive logins.
"Most of it does not work" is not what the audit shows — most of it works, and too much of it
exists.

## Items

- [x] **One passthrough per CLI, not a task per subcommand**
  - [x] 34 relay tasks deleted; `mise run emdash -- …`, `mise run emdash-plugin -- …` and `mise run skills -- …` replace them. 130 tasks → 99
  - [x] the hosted plugin registry is the default; the local one is used only when it is answering. `plugin:search` works again
- [ ] **Move the nushell out of TOML into a module** — the change everything else depends on
  - [ ] `nu/harness.nu` (split by area as it grows) holds the logic as exported commands; a task body becomes one line that calls one
  - [ ] hidden helper *tasks* become *functions*: each `^mise run x:_helper` today starts a new mise and a new nushell. Record `repo:apply` and `check` wall time before and after
  - [ ] shared code exists once: the exit-code wrapper, the dev-database path, the `--url` handling, the JSON reader
  - [ ] `nu --ide-check` runs on real `.nu` files — no more writing each body to a scratch file — and an editor gets live diagnostics
  - [ ] real unit tests with `std/assert` for the seed merge and the registration generator, run by `check`; the fixture-comparison task goes
  - [ ] `mise.toml` is tools, settings, daemons and task declarations: under 400 lines
- [ ] **Flows, not steps** — what a dev sees in `mise tasks ls`
  - [ ] the vocabulary: `setup`, `dev`, `check`, `doctor`, `deploy`, `snapshot`, `restore`, `reset`, `logs`, `open`, `plugin:new|dev|probe|remove|roundtrip|release`, `content:set`, `schema:diff`, `registry:up`, and the three passthroughs
  - [ ] everything that is a *step* of a flow is hidden or a function: `seed:build|validate|apply`, `config:apply`, `src:clone-*`, `site:sync|install|setup`, `mcp:token-admin`, `plugin:link|build|validate|typecheck|test|audit`
  - [ ] `site:build`, `site:deploy-dry`, `site:deploy` become `deploy`, `deploy --dry`, `deploy --build-only`
  - [ ] `registry:*` (8 tasks) and `plugins-site:*` (3) become `registry:up` and `registry:down`, each doing its whole job
  - [ ] no more than 25 visible tasks, and `mise tasks ls` fits on one screen
- [ ] **Comments say what, the docs say why**
  - [ ] a task carries at most three comment lines; the history of each bug moves to `docs/agents/` or goes
  - [ ] the header of `mise.toml` is the quick reference and nothing else
- [ ] **Every remaining task is proven, and stays proven**
  - [ ] run the ones this audit skipped: `registry:up`, `site:check`, `deploy --dry`, `deploy`
  - [ ] a task that cannot be made to work is deleted, not documented
  - [ ] `repo:selftest` keeps covering the checkers after the move to a module
- [ ] **Ops flows that do not exist yet** — what "dev, ops, etc." still lacks
