# 2026-10-06 — Our own site, built with the harness; emdashcms.com as the reference

**Status:** active — **1 of 9 done** — item 2 is the owner's and gates items 3 to 7

Two linked things. First: keep a reference checkout of EmDash's own site,
`emdash-cms/emdashcms.com`, the way we keep the templates and the EmDash source — because it is the
one production EmDash site whose source we can read. Second: put our own site up, on EmDash, using
only this harness.

The second is the real test. Every flow here has been proven on a template with a seed on top.
Nobody has yet built a site with it. Where the harness cannot do what a site needs, that is a
harness item, written below as its own checkbox — the site drives the fixes.

What the reference site teaches is in [`../emdashcms-com.md`](../emdashcms-com.md). EmDash itself
is in [`../emdash.md`](../emdash.md).

**Effort, honestly:** items 1 and 9 are an hour each. Item 2 is the owner's, minutes once decided.
Item 3 is an hour if nothing breaks. Item 4 is a day and is the one that matters. Items 5, 6 and 7
are a day together, most of it waiting on Cloudflare and on other plans. Item 8 is half a day.
The site's design and words are not in this plan and are not small: emdashcms.com is about 11,600
lines of `src/`.

## What is verified, and what is a guess

**Verified by reading `emdash-cms/emdashcms.com` at `613eba1`** (details and line numbers in
`../emdashcms-com.md`):

- It is a Cloudflare site forked from the `marketing-cloudflare` template; nearly every file under
  `src/` differs from the template's.
- It pins `emdash@0.38.0`, not 1.x. Its Worker entry and its block plugin are the 0.x forms.
- It has no licence file. We may read it; we may not copy it.
- It sets `site:`, a cache provider, custom domains, a host redirect in the Worker, Cloudflare
  Access, and its own `robots.txt`, sitemap index and RSS. No official template sets `site:` or a
  cache provider.

**Verified by reading this repo** (cited by function name; `nu/` is being edited while this is
written):

- `checkout` in `nu/site.nu` already clones or updates any repo at any ref. `clone-templates` and
  `clone-emdash` are two three-line callers of it. `main source` in `nu/main.nu` calls only
  `clone-emdash`, and takes no argument.
- `clone-templates` is called by `main setup`; `clone-emdash` by `main source` and by
  `nu/registry.nu`.
- **A project has nowhere to keep its own pages.** `configure` copies exactly two files from
  `config/` into the site (`astro.config.mjs`, `wrangler.jsonc`), writes `local-plugins.mjs` and
  the merged seed. `copy-template` deletes `.src/site` and copies the template again. The README
  says "Never edit `.src/site` — it is rebuilt". `grep` for an overlay of `src/` finds none.
- `deploy` refuses a Cloudflare deploy when the Worker has no `EMDASH_ENCRYPTION_KEY`
  (`deployed-has-key`), and its hint is a hand-typed `wrangler secret put` inside `.src/site`.
  There is no task that puts a secret.
- `deploy` needs `DEPLOY_URL` set before the first deploy.
- The newest release is `v0.4.1` (`gh release list`); `HARNESS_VERSION` on `main` is `0.4.2`. The
  installer fetches the latest release, so a new repo gets 0.4.1 until the next tag.
- `harness.toml` describes the `content:set` task with `parts top-plate '{"material":"Steel"}'` —
  the CAD example, inside the harness half.
- This repo's own project (`mise.toml`, `config/`) is the CAD example on `starter-cloudflare`, and
  is what `mise run verify` runs against. Its `VERIFY_*` settings name an R2 bucket,
  `cad-documents`.

**Guesses — each has a step below that settles it:**

- That `install.sh` in an empty repo with a non-default template ends with a running site. CI runs
  the installers; nobody has run one for a repo that is then kept.
- That `wrangler secret list` and `secret put` behave sensibly for a Worker that has never been
  deployed. If not, the first deploy of any new site is blocked by `deployed-has-key`.
- That copying a project's `src/` over the template is enough for a real site (item 4). It may not
  be: the edit loop restarts the site on every change.
- That passkeys registered on `workers.dev` stop working after a move to a custom domain
  (`docs/emdash.md` § What a real site needs says they are bound to the setup domain). Not run.
- That the commit message "blog-cloudflare passes the full verification" (`c31c1e1`) still holds.
- That `doctor --url` works against a custom domain as it does against `workers.dev`.

  **Why a new repo and not this one.** This repo's `mise.toml` and `config/` are what `verify` runs
  against; a real site in that slot makes every harness check depend on the site's content. A
  separate repo is also the only honest test of the product: it gets the harness through
  `install.sh`, takes fixes through `mise run upgrade`, and cannot quietly patch `nu/` in place —
  so every gap becomes a release here instead of a local edit there. And it proves the rule that
  nothing project-specific lives in the harness half, which item 9 shows is not yet true.
